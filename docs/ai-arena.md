# AI竞技台

本包源码位于 `lwb/packs/ai-arena/`，开发时自动发现；随带清单见 `lwb/desktop/editions.json`（社区版与商业版都已包含 `ai-arena`）。

## 当前范围

- 支持五子棋、中国象棋和可选择 6 / 8 / 9 人的狼人杀。人数档位登记在游戏定义的 `seatOptions` 上（默认 6），牌型为 6 人「狼 2 · 3 神 · 1 民」、8 人「狼 2 · 3 神 · 3 民」、9 人「狼 3 · 3 神 · 3 民」；主持人不占模型席也不参与裁决，夜序为狼刀、查验、女巫、黎明，白天先按座位发言再依次投票，平票复投一次、再平票无人出局。猎人夜死或票出都可开枪。
- 狼人杀是隐藏身份游戏：局面是唯一真相，`observe` 只给出该座位此刻允许知道的内容（狼人拿到同伴与狼聊，预言家拿到自己的查验，女巫只在用药时拿到当晚刀口）。观战与回放则给观众完整视角：全员立绘席卡、身份标记、出局与阵营终局都画出来。
- 每局按 32 位随机种子与人数档位重新发牌，两者都记在 `config` 里（`seed`、`seats`）；同一 seed + 同一档位 + 同一动作序列可以离线复现整局，观战逐手回放、离线回放的席位舞台与主持人台词都靠这一份规则重放还原。牌型本身不固定。
- 五子棋采用 15×15 自由规则，黑方先手，无禁手，连续五颗及以上获胜。规则判定采用 MIT 许可的 `@algorithm.ts/gomoku@4.0.5`；本包只做坐标、占位、轮次和状态适配。
- 中国象棋使用标准 10×9 棋盘，红方先手，支持将、士、象、马、车、炮、兵的合法走法，含马腿、象眼、九宫、过河、炮架、将帅照面、自将检查、将军、将死、困毙与吃将；胜负和裁决模型见[象棋的裁决模型](#象棋的裁决模型)，边界见[已知限制](#已知限制)。客户端、回放、离线 HTML、Markdown 战报和视频表现层显示楚河汉界、九宫、32 枚红黑棋子与起止坐标，视觉沿用五子棋竞技台的页面结构与窄屏布局。
- 两名选手选择 DSH 已配置的模型路由，允许同模型自我对弈。推理强度在模型目录公开支持时可选择；比赛只记录所选路由与模型 id，不推断底层真实模型。
- 每名选手使用各自的连续 DSH Agent Session，每次发送当前棋盘、公开的规则、最近着法与重复/无进展计数，以及必要的纠错反馈（象棋的披露分层见[象棋的裁决模型](#象棋的裁决模型)）。无工具预设启用 DSH 原生自动上下文压缩；单次回复被截断时在同一 Session 中有限补全。暂停恢复复用选手会话，保留比赛审计；官方对话窗口仅供回看，不提供可干扰比赛的输入框。
- 所有选手使用同一系统指令；对手发言不进入参赛请求。选手发言是模型输出的简短表达，不声称是完整内部推理；实际返回的 reasoning 仅保存在原始记录中。
- 非法坐标、占用落点、回复格式不合法均记为违规，默认重试一次，再次违规判负。服务错误或截断暂停比赛，由用户决定继续，不计为棋力失败。
- 暂停在当前回合结算后生效；取消立即停止调用，迟到回复不提交为落子。关闭浏览器不停止比赛；停止 Host 或卸载包中断比赛，重新加载后需要人工继续。
- 场景层不设置走子上限、调用上限、单步时限、每步生成 Token 或累计 Token 上限。输出容量与上下文处理交由 DSH、模型适配器和服务商的原生配置；这不代表模型和服务商没有边界。调用和已报告 Token 继续作为审计统计，未报告用量明确显示不完整，不伪造费用。
- 比赛按棋规判定终局，保留违规重试、格式补全、暂停、取消与错误处理。象棋只有吃将、将死、困毙三种胜法和「连续 120 半回合无吃子及兵卒向前推进」一种和棋；**重复局面不是裁决**，只作为信息公开给选手。快照读取与取消结算的基础设施等待边界仍保留。
- 不提供快速或深度模式切换。旧比赛恢复时清除场景预算与时限配置，显式清除旧会话输出策略并记录迁移事件，后续按 DSH 默认执行。已结束的历史比赛及其原始请求、输出、结果保持原样。
- 关键手档位默认为「吃大子 / 将军」。档位默认值、下拉首项与视频固定档位保持一致；只取「将军」会丢掉连续兑子的高潮段落。

## 象棋的裁决模型

规则版本 1.1.0 取消了「局面出现三次即判和」。这不是放松规则，而是承认那条规则回答错了问题。

- **为什么取消次数判和。** 次数只说明棋局是否停滞，不说明双方是否赢不了，而它却是**行为依赖**的：同一张盘面，双方多绕两圈判和、少绕两圈继续下。它会把胜局判和——1.0.0 下的一场实盘就是如此：黑方子力 14:2 大优、红方只剩光帅加一仕，黑方在第 126—136 手用马反复叫将，第 136 手触发第三次重复即判和。这是可复现的回归夹具 `test/fixtures/xiangqi-perpetual-check-loop.json`。
- **终止性不依赖重复裁决。** 无进展计数只在**吃子**或**兵卒向前推进**时归零，两者都不可逆且有界：吃子至多 31 次，兵卒纵向前进每方至多 30 次。归零事件有限 ⇒ 总手数存在约一万手的硬上界，比赛必然终止。所以去掉重复判和后，终止性由无进展规则单独保证。
- **历史裁剪与计数正确性。** 吃子或兵卒向前推进之后，此前的任何局面都不可能再出现，因此重复历史在这些时刻裁剪到当前局面，长度被无进展上限约束在 120 以内；被裁掉的条目本来也永不匹配，所以上报给选手的重复次数仍然精确。
- **披露分三层。** 构成性规则（胜负和如何裁决）必须给，写进系统指令与游戏说明；局面状态（最近着法 `recentMoves`、当前局面出现次数 `positionRepeats`、每个合法着法走完后的重复次数 `repeats`、无进展手数 `noProgressPlies` 与阈值 `noProgressLimit`）必须给，否则等于用一个选手无法建模的量来影响它的结果；**策略建议不给**，系统指令只陈述规则事实，不写「领先时应当变着」这类教练话术。
- **代价。** 和棋会更晚出现：停滞的棋局现在要走满 120 半回合才判和，长局与模型调用成本上升。无进展规则本身仍是与次数规则同类的近似——它同样不判断「是否真的赢不了」。它只是不再把胜局判和，并把裁决从「双方绕了几圈」改成「棋局多久没有实质进展」。
- **披露的每手开销。** 最近着法用紧凑记法（手数+走子方+棋子+起点行,列>终点行,列，x 吃子、+ 将军，如 `136黑馬8,8>10,7+`），16 手约 257 字节，比等价嵌套 JSON 省约 7 倍。开局满子力时每手提示词约 3.3 KB（主要花在约 40 个合法着法与各自 `repeats`），残局约 1.1 KB。

## 主持人播报

狼人杀的「主持人」不是模型席位，也不是一个会说话的 AI 角色，而是**规则层的确定性播报**：发牌、夜序、天亮、投票统计与裁决本来就由规则完成，播报只是把这些公共事件写成人话。

- **台词来源。** `werewolf.mjs` 在每个阶段进入与每个公共事件发生时把台词写进 `state.narration`。同一次行动里连续推进的多个阶段会合并成一条，观众看到的是一句完整的话，例如女巫那一手既是天亮结算又是白天开场：「天亮了，昨夜 3 号出局。第 1 天，请存活玩家依次发言。」
- **挂点：台词说在「本手开场」。** 规则是在行动推进**之后**才写 `narration` 的，而画面与配音的契约是「主持人先说、选手后说」，所以展示层把每条台词挂到**进入新阶段的那一手**（上一步打完之后生效的那一句），而不是它被写出来的那一手。否则结算播报会提前到造成它的那一手：「发言结束，请投票放逐一名玩家。」会出现在当天最后一位发言者的帧上，与他的发言同帧、配音还排在他的发言前面。整局最后一条结算播报（谁被放逐 / 猎人带走了谁）没有「下一手」可挂，由终局卡接管（文案与配音都挂在手数 + 1 那一格）。
- **一帧只讲一个时刻：这一步开场。** 台词锚在「本手开场」之后，**存活、出局、天数与阶段也取同一刻**——逐手快照里的 `alive` 是「这一步开场时还活着的人」，`deaths` 是「相对上一帧的增量」（也就是这一步开场时主持人刚宣布完的那批出局）。于是**宣布与出局同帧**：本手造成的出局出现在**下一手**那一帧，由主持人当场说出来、画面同时灰化并播放红叉，进度条上的出局刻度也落在同一帧。修之前两者差整整一手：8 人局离线回放 40 帧里 37 帧在叠；复投最后一票那一帧就把被放逐者画成「出局」，而主持人还在说「进入复投」；夜里被刀的人在夜里就灰化，天亮宣布时才第一次被说出来（等于提前透刀口）。最后一手的结果同样没有「下一手」可挂，由终局卡承接：`replay/data.mjs` 因此另给 `finalAlive` / `finalDeaths`，终局帧的席位名单与出局动效取它——否则最后一手出局的人会在终局席位上「复活」。口径由 `test/werewolf-replay.test.mjs` 的总闸门守住：**台词里宣布谁出局的那一帧，谁必须已经出局；没被宣布的人不许提前出局**（观战、离线回放、MP4 共用这一份投影）。
- **三条硬约束。** 不参与裁决（不改局面、不判违规）；只读公共信息（不碰查验结果、狼队名单、身份）；只给观众（`observe` 不包含 `narration`，选手提示词零变化，`test/werewolf.test.mjs` 有断言守住）。
- **三处同源。** 观战页、离线回放与 MP4 读 `werewolf-projection.mjs` 同一份逐手快照：台词、存活、出局、天数与阶段都取自这一步开场那一刻，观战往回拖画第 k 步的快照；跟随最新一手分两种现场——下一位已经在飞时用记录自己的 `state`（观众刚听完上一位的结算播报，画面与那句同帧），空闲停在最后一手时仍用最后一手的开场快照；离线回放与视频再经 `replay/data.mjs` 落进产物（终局帧另取 `finalAlive` / `finalDeaths`）。因此三者逐字一致，不需要为台词落盘，也不影响 `seed + seats + 动作序列` 的复现契约。
- **不升版本。** 播报不改变规则语义、行动者队列或观察裁剪，单独合入时不需要动 `werewolf.version`；人数档位化才需要（1.0.0 → 1.1.0）。
- **画面。** 台词卡挂在舞台抬头下方（`.ww-host` / `.ar-stage-host`），原来单独的出局横幅并入台词，避免「抬头 + 出局条 + 台词」三层重复；席卡红叉、灰化与「出局」标记仍然保留。
- **不做的事。** 不做自由文本生成、不新增模型调用、不解释局势或点评选手。
- **配音。** 勾选「生成声音」后，主持人台词与选手发言一起合成：主持人用固定参考音色 `assets/voices/host.mp3`（不参与选手匹配、不与任何选手共用），同一句不重复合成（按「换句」取，一手至多一段）。一手里主持人先说、选手后说，两段合成一条音轨；离线回放用两个播放器按主持人时长把发言往后排。终局卡那一手（手数 + 1）承接最后一条结算播报的配音：卡本身仍是 4 秒，但要放得下这一句，时长表按终局那一格的实际音频拉长。

## 画面与视频

离线回放与视频共用 `lwb/packs/ai-arena/replay/` 这一份画面源：`page.html` 骨架、`scene.css` 布局与配色、`shell.css` 交互外壳、`app.js` 离线播放器、`markup.mjs` 帧驱动构建器、`data.mjs` 数据投影、`timeline.mjs` 时间轴；生成物由 `build-replay.mjs` 产出，已并入 `npm run arena:build`。两侧共用同一份手数、关键手、连子与终局文案，不再各自投影一遍；狼人杀的逐手局面由包根目录的 `werewolf-projection.mjs` 提供，观战页、离线回放与视频共用它，而不是各自重放规则。

- **「谁在执行」是画面的一个主角，不是记分条上的一行元数据。** 每一手都有一张执行者卡（`.turn`）：席位强调条 + **模型形象（带左上角 logo 徽标）** + 模型名（横屏 30px、竖屏 32px，狼人杀 26 / 30px），右侧标出席位（`红方 · 先手`）或步数；开局指先手、逐手指本手、终局换成胜方口径的金色。此前身份只落在两条 26—28px 记分条的底色上、名字 12—13px，缩到手机宽度（393pt，约 0.55×）后只剩约 6.5pt，等于不可读——这是这次改造要修的观感缺陷。字幕署名同时抬到 20—22px 并挂「本手发言」胶囊，让画面最大的那句字自带归属。字号下限由 `test/replay.test.mjs` 守住，不会再被悄悄改小。
- **模型身份是一张表：一个模型 = 一个家族 = 一个 logo + 一个音色 + 一个形象。** 在这之前三件事各存了一份匹配规则，键还对不上（音色键 `gpt`／图标文件 `chatgpt.png`／形象家族键 `chatgpt`），「同一个模型在三处是不是同一个家族」只能人肉核对。现在只剩 `models.mjs` 的 `MODEL_FAMILIES`，`voices.mjs`（音色与 logo）与 `presentation.mjs`（形象）都读它。形象**跨游戏共用**：五子棋、中国象棋、狼人杀共用同一套家族形象；棋类不产出身份徽记（`ROLE_MARK` / `ROLE_NAME` 是狼人杀专属），否则会被读成「棋类也有阵营」。素材是**带 alpha 的 WebP**（`assets/models/{full,bust}/`），「只有人物、没有底板」因此在白色侧栏上成立——原先的 JPEG 背景是纯黑 `(1,1,1)`，直接放上去就是一块黑方块。
- **形象进执行者卡，并且只有本手有发言才画人。** 有形象时 logo 退到人物左上角当徽标；没有发言（开局、终局、以及没有发言的手）时这一格里只剩 logo，盒子仍占位，所以卡片高度逐手不变、侧栏不跳。三档高度契约由「游戏 × 画幅」**一次性**定下（不按每手字幕长短动态判断，否则卡片会跟着发言长短跳）：**标准档** 112—114px、形象 66×86 在模型名左侧（全部横屏 + 五子棋/狼人杀竖屏）；**紧凑档**保持卡片自然高度、形象 46×58 放右侧（象棋竖屏——象棋棋盘在竖屏是 720×796，侧栏只剩 484px、叙事区 95px）。狼人杀横屏为此把回合记录由 3 条收到 2 条让位，观战页没有执行者卡、形象落在它的「谁在说话」块（`.ar-speaking`）里，尺寸按容器宽度（`cqw`）跟随窗口收缩。
- **换手节拍：执行者卡先到 → 落子随后（+0.12s）→ 台词最后（+0.22s）。** 数值是 `markup.mjs` 的 `TURN_IN` / `STONE_DELAY` / `SPEECH_DELAY`：视频侧按帧算成内联样式，离线 HTML 用 `scene.css` 同名关键帧的 `animation-delay` 复刻同一节奏，两边必须一起改，`test/replay.test.mjs` 会拦住不一致。执行者卡自身是上滑 + 强调条展开 + logo 微缩放——手机上静态的底色切换不会被看见，动效才是「换手了」的信号。
- 狼人杀把「本手执行」与「胜方」拆成两个颜色：当前行动席位改用蓝环 + 更大上抬（此前是金框，与胜方金框同色，终局两者还会同时出现），金色只留给胜方阵营。狼人杀没有棋盘，侧栏的执行者卡整块顶替了原来的 hero 行（天数与阶段在舞台抬头里已经有了，不再重复一遍）。
- 竖屏 9 人是 3 列 × 3 行，席位栅格原本顶在主持人台词上（台词到 140px、栅格从 131px 起）；9 人竖屏把席卡压到 124px 把栅格推下去，8 人（4 列 × 2 行）本来就有富余，不受影响。
- 执行者卡占掉了侧栏顶部，横屏的「回合记录」因此由最近 5 手收到 4 手（狼人杀 3 条）。**「可收缩的一方让位、本手发言永远优先保留完整高度」在 2026-10-09 之前只是意图，实现正好相反**：`.speech` 是 `flex:1`（basis 0）只拿剩余空间、`.recent` 是 `flex:0 1 auto` 反而按内容拿满，两块又都不裁剪，于是「内容比盒子大」直接变成重叠（见下一条）。

- **观战页的席位舞台按「安全区契约」排版：8 / 9 人是卡片变小一档，不是把画面撑破。** 舞台从上到下依次是抬头、主持人播报（终局换成胜负卡）、场景留白、本手台词、席位条带，每一段都参与布局流。此前抬头（`top:5%`）、主持人（`top:20%`）、台词（`bottom:43.5%`）各自绝对定位，那几个数值只对 6 人局成立；席卡高度又由列宽推（`aspect-ratio:3/4` + `width:100%`）。两个假设在 8 / 9 人下同时失效：列数从 6 变 4 / 5、行数从 1 变 2，条带变成画幅的 117%（8 人），第一排被 `overflow:hidden` 裁掉头部；9 人（92%）则从台面顶部下方 23px 起铺满，昼夜场景、抬头与主持人台词全被盖住，`bottom:43.5%` 的台词条正好落在人物脸上。现在列数与行数一起由 `werewolfCastLayout` 给出（横屏 6 → 6×1、8 → 4×2、9 → 5×2，竖屏沿用 3 / 4 / 3 列），条带高度按行数取（`--ar-cast-band`：1 行 40% / 2 行 48% / 3 行 52%），席卡高度由行高决定、宽度填满单元格、立绘按 2:3 居中留边；条带是唯一可收缩的那一段（`flex:0 1 auto`），窄窗口先让席卡变小，抬头、台词与胜负卡不会被挤出画幅。舞台同时是查询容器，字号按舞台宽度（`cqw`）缩放；窄舞台（≤600px）下席位署名让位给立绘，姓名与身份在右侧「选手发言」表头与回合记录里都有。宽窗口下的立绘与离线回放同量级（舞台 1341px 时约 92×139，离线 1280 画幅是 92×138）。契约由 `test/werewolf-stage.test.mjs` 守住——列数行数、条带高度、布局流与高度预算；几何实测覆盖 6 / 8 / 9 人与 700—2537px 的窗口宽度（裁切、溢出、遮挡三项均为零）。

- **「这个模型是什么身份」写在说话的那一行上。** 观战页与离线回放/视频的「选手发言」署名与「回合记录」逐行带「席号 + 徽记 + 中文名」（如 `2 号 qwen3.8-max` ＋「狼 狼人」）。此前只有模型名：同供应商的不同模型经常同名（一场实盘 9 人局里两席都叫 `deepseek-v4.1-flash`），观众得自己把名字对到舞台席卡上，而画面最大的字（发言正文）恰恰不带归属。身份一律取落盘那一份牌（`presentation.seatIdentity` 读 `state.players`，与舞台席卡、`replay/data.mjs` 的 `seats` 同源），往回拖也按同一份牌，不会各发一套；棋类没有身份，一个身份元素都不产出（`test/replay.test.mjs` 守住）。观战侧栏另统一了两处口径：狼人杀的「第 N 手」改「第 N 步」、「等待第一步走子」改「等待第一步行动」，并且没有行动者时不再退回 1 号——开局那一刻 `activeTurn` 还没落上，退回 0 会把署名与身份都算到 1 号头上。
- **身份标签的版式取舍。** 视频横屏狼人杀侧栏固定 404px，一行要塞「席号 + 模型名 + 身份 + 本手发言 + 动作」。席号与身份 `flex:none`，模型名先被截断（`.sn` 改为 `nowrap` + 省略号；同名信息在身份榜与执行者卡上都还有），与「本手发言」胶囊重复的「发言」动作标签在狼人杀里不再重复显示。观战页侧栏是浅色卡片，舞台那套「村民白底深字」照搬会看不见，所以 `styles.mjs` 给 `.ar-role` 自带浅色配色与深色主题覆盖（猎人徽记琥珀底配深字）。席号与身份标签的字号下限由 `test/replay.test.mjs` 守住（≥14px）。
- 狼人杀的**昼夜场景**在 `assets/werewolf/scenes/`，由 `build-werewolf-art.mjs` 生成 `werewolf-art.mjs`；**模型形象**（跨游戏共用）在 `assets/models/{full,bust}/`，由 `build-model-art.mjs` 生成 `model-art.mjs`（连同圆形 logo），观战、离线回放、MP4 三处共用；主持人台词只用文字胶囊，不新增素材。离线回放只内联这一局真正用到的素材，仍不依赖网络。

- 视频时长按 `(手数 + 1) × 每手秒数 + 4 秒终局卡`，与离线 HTML 的 `FINALE_MS` 对齐：五子棋 20 手＝67.0 秒，象棋 136 手＝415.0 秒。勾选「生成声音」后，有配音的那一手改为 `max(每手秒数, 音频时长 + 0.35 秒)`；狼人杀那一手的音频时长是「主持人 + 选手」两段之和，终局卡仍是 4 秒，只是狼人杀最后一条结算播报挂在终局那一格，有配音时按它拉长。

- 游戏库卡片与赛制实现解耦：`presentation.mjs` 的 `GAME_CARDS` 为每款游戏登记一句摘要、事实标签与封面种类，多档位游戏再按 `seatOptions` 现算一条人数标签前置。封面就是真实对局画面——棋盘用同一份 `boardSvg` 现画（五子棋是「黑 4 连、再一子即胜」的示例手顺，象棋是开局 32 子），狼人杀复用夜景与六席立绘（**封面固定 6 席演示牌型，不随档位变化**），没有登记的 `gameId` 退化为名字首字海报，所以封面不会出现空白方块。卡片锁 16:10 封面、三张等高、页脚吸底，每款一套浅色与暗色配色，页脚显示该游戏进行中或已完成的场次。封面媒体必须挂在自带尺寸的包裹层（`.ar-game-board`）上，`test/game-cards.test.mjs` 会拦住「把 SVG 再包一层无尺寸 div」这类回归。

## 数据与恢复

`<pack-workspace>/data/matches/<match-id>/match.json` 是每场比赛的事实源，包含配置、规则版本、模型身份、棋盘和事件；串行写入并通过原子替换提交。事件依次记录 request、response、move/invalid、error/interrupted、finished/cancelled。

原始回复先保存为 pending，再校验并提交动作。Host 在收到回复后中断，继续时可消费已保存的回复，不重复请求。请求已经发出但未收到回复时无法确认供应商是否完成或计费，不自动重新调用，先暂停等待用户决定。重启前请求仍计入调用次数。

恢复比赛前检查游戏规则版本；版本变化时保留记录并要求创建新比赛，避免按不同规则继续旧局。

完整 JSON 下载包括各回合实际输入、输出、用量、reasoning 和配置；Markdown 是便于阅读的战报。离线 HTML 只内联画面所需数据（不含原始请求、系统指令和推理文本），在浏览器里用与观战、视频同一份 `boardSvg` 现画棋盘，不依赖网络、模型或其他包，支持横竖屏切换、跳步、播放、关键手强调档位和纯画面模式。导出文本和 HTML 对模型文本作相应安全编码。

## 比赛记录列表

列表的标题与结果都在显示层从记录派生，不改历史 `match.json`。标题统一由 `presentation.matchTitle` 生成并保持幂等：棋类记录创建时只有「A vs B」，1.0.0 的狼人杀更是「狼人杀 · A / B / …」，显示层按 `game.id` 补游戏名前缀，因此列表、回放面包屑、战报、离线回放与视频五处共用同一份标题，旧记录无需迁移、也不会叠成双重前缀；没有 `game.id` 的旧数据不推断游戏名。`host.mjs` 同时让新记录在创建时就自带游戏名（棋类「五子棋 · A vs B」，狼人杀保持「狼人杀（N 人）· A 等 N 位」）。

结果列读列表投影里已有的 `result`，不额外查询：棋类 `winner` 是座位号，取选手名显示「X 胜」；狼人杀是阵营，显示「好人阵营胜 / 狼人阵营胜」；和棋统一显示「和棋」（五子棋的「平局」不再单独出现）；取消与未结束显示占位符「—」，列宽不随内容跳动，完整裁决话术挂在悬停 `title` 上。搜索索引覆盖获胜方文案，狼人杀的行内计数单位是「步」、棋类是「手」。

## 视频渲染

视频通过现有 Remotion 技术栈渲染固定模板，棋盘与台词来自同一份比赛事件；每步默认 3 秒，额外保留终局画面。横屏为 1280×720，竖屏为 720×1280，H.264 MP4。画面包含文字发言。比赛记录里可以勾选「生成声音」：未登录 LWB、语音服务不可用或可用积分低于目录最低门槛时，勾选不可用，无声导出保持可用。勾选后用 LWB TTS 按每手发言合成语音，音色、圆形 logo 与角色形象按 `models.mjs` 同一张家族表匹配，没有专属素材时用通用音色、通用 logo 与通用形象，两名未匹配选手不共用同一条通用音色；狼人杀的主持人播报另用固定参考音色（`assets/voices/host.mp3`），与选手音色互不共用。配音按句缓存在比赛目录（缓存键含音色与文本，主持人与选手各自成键），同一句再次导出不再请求。写入缓存前把每句和参考音色拉到 -16 LUFS、真峰值不超过 -1.5 dB：先量出综合响度与真峰值（`loudnorm` 的 JSON 统计），一次性给足增益，再用前瞻限幅把越过真峰值上限的峰压住——语音的波峰因数常在 15 dB 上下，`-16 LUFS` 配 `-1.5 dBTP` 本来就装不下，压峰而不是砍增益才是句子之间响度一致的前提（砍增益正是旧实现让部分句子小声 13 dB 的原因）。限幅天花板比上限再低 1 dB，抵掉 MP3 编码抬高的那部分真峰值（实测最多 0.6 dB）；`alimiter` 缺失的精简 FFmpeg 退回两遍 `loudnorm`，只贴到真峰值上限为止（波峰因数高的句子低 2–3 LU），方向仍然正确。量不出来（近乎静音）或产不出文件时仍使用已生成的音频，不中断回放和视频。响度口径记在 `LOUDNESS_VERSION` 上：它同时是片段缓存名与成片复用键的一部分，改对齐链路必须一起改它，旧片段与旧成片才会一起失效；重导时先拿盘上旧口径的同一句重新对齐，不重复调用 TTS。有声回放与有声视频都在后台合成，进度记在这场比赛上，离开页面不会停止。离线 HTML 把音频内联为 data URL，仍不依赖网络；MP4 在画面渲染后用 FFmpeg 按每手起始时间混入音轨，一手里主持人先响、选手发言从主持人结束后开始，终局那一手（狼人杀最后一条结算播报）排在终局卡的起始时间上。没有 BGM、AI 自动解说或精华剪辑——主持人是规则确定性播报，不是模型即兴解说。

渲染需要 FFmpeg、ffprobe 和 Chrome。macOS 默认使用已安装的 Google Chrome，其他环境可设置 `LWB_REMOTION_BROWSER_EXECUTABLE`。成片用 ffprobe 检查尺寸和时长。下载通过有界分块 RPC，绑定导出版本；不沿用口播包的整文件 80 MiB 读取方式。

## 成片复用

一场比赛终局之后内容就冻住了（导出只对 `finished` / `cancelled` 开放），渲染本身又是确定性的（画面里所有随时间的量都由 `markup.mjs` 按帧算成内联样式，`video.mjs` 关掉了全部 CSS 动画与过渡），所以同一组渲染输入重复导出只会得到同一份字节。导出前按渲染输入算一个键：参与渲染的源文件内容摘要 + `PIPELINE_VERSION`（Remotion / FFmpeg / 编码参数变了要 +1）、`replayData` 的摘要（走子、发言、选手、结局任一变化都换键），再加上画幅、每手秒数、是否配音（配音再带响度版本，因为时长来自按句缓存的 mp3）。键相同就把上次的成片直接交回，不再重跑 bundle、逐帧渲染与混音——这是整条链路里最贵的一段。索引与产物都落在 `data/matches/<match-id>/` 里（索引是 `match.json` 的 `exports` 字段），重启后照旧复用；每场最多留 8 份，超出的连同文件一起淘汰。

产物文件名也带键（`video-<键>.mp4` / `replay-<键>.html`），无声与有声、横竖屏、不同每手秒数各自成文件，不再互相覆盖。带键之前的老记录没有 `file` 字段，下载时照样退回 `<画幅>.mp4` / `replay.html`；新一轮导出成功后那个旧命名的文件会被清掉，不留孤儿。客户端按索引找当前选择对应的产物：找得到就把主按钮换成「下载有声 MP4 / 下载 MP4」（一次点击拿到文件），另给一个「重新渲染」图标强制重跑；`videoChunk` 既认当前导出 id，也认索引里的缓存键，所以下载不必先让 `export` 绕一圈。索引只描述盘上真还在的成片——文件被外部清掉时，下载会摘掉那条索引并把指向它的记录标为失败，界面自动回到「导出」。无声离线回放不进这套缓存——它是纯函数现算的，不落盘、不请求语音，永远跟着最新模板走。

## 扩展边界

`games.mjs` 在竞技包内部管理游戏定义。每个游戏提供身份与版本、人数（`players` 为默认档位）、可选档位（`seatOptions`，缺省视为 `[players]`）、create、observe、apply；宿主按 `state.pending`（当前允许行动的座位队列）逐人调度，终局、错误、存储和回合调度仍由宿主负责。人数档位走 `request.seats` → `config.seats` → `create(seed, seats)` 一条链：校验在宿主，复现输入在配置，回放按 `config.seats` 重放。隐藏身份游戏靠两件事落地：`observe` 按座位裁剪可见信息，`pending` 声明每一步的行动者。**主持人播报不扩展这套协议**——它是 `state.narration` 的纯投影，既不是行动者也不占席位。要再加同时行动或多人同回合的游戏，仍需扩展调度协议——但不必再改提示词的 JSON 形状，狼人杀已经证明「单一行动者队列 + 私有观察」这条路可行。浏览器和视频需为新游戏增加专属画面适配，狼人杀的席位舞台就是这类适配的样板。

竞技台不暴露一次性模型 completion 绕过路径；模型调用统一受 DSH Session、能力包卸载信号、取消信号和权益边界管理。普通对话、口播 Agent、测评会话继续使用各自原有的 DSH 路径。

## 已知限制

- **模型的角色形象没有「重出」过，是从原立绘派生的。** `assets/models/` 由 `.prototypes/arena-model-art/derive.mjs` 从 `assets/werewolf/characters/*.jpg` 派生：原图背景是纯黑（实测 1—18）而最暗衣物也在 30 以上，所以黑底键几乎是精确的（连通种子只取上半幅与左右边距——半身立绘在画幅底部被裁切，从底边取种子会把衣摆当背景吃掉）。派生后 40 张 full 共 591 KB，是原 JPEG 的 1.04×。将来换成原生带 alpha 的立绘时脚本会直接透传，不需要改代码；但**当前这一批不是重新生成的**，取景仍是原来的半身构图。
- **狼人杀横屏的发言卡底部内边距会被裁掉约 21px。** 执行者卡为放形象从 79px 长到 112px，回合记录 3 → 2 条只让回 12px。裁掉的是行距与内边距，字形不受影响（`test/replay-sidebar.test.mjs` 按「字形框 + 行距」断言）。要彻底消掉需要再收紧身份榜行高或记录下限，本轮没做。
- **棋盘类的离线产物体积涨了。** 形象跨游戏共用后，五子棋/象棋的离线回放也要内联选手形象：五子棋 87 → 163 KB、象棋 95 → 206 KB（象棋还要多带胸像档，因为它的竖屏走紧凑档）；狼人杀 +23 KB。`client.js` 由 0.97 MB 增到 1.52 MB——多出的是**胸像档**与带 alpha 的 WebP。要压可以按 `assets/models/bust/` 只留主图变体（紧凑档没有胸像时会退回半身），但那会牺牲象棋同族对局的区分度。

- 视频侧不区分「播放推进」与「跳步」，每一步都按播放推进的动效渲染；离线 HTML 拖动进度条时不触发动画。狼人杀的出局红叉与入场动画同理，只在播放推进时出现。
- 终局口径在软件内与离线回放有一处**刻意**的差异：软件内按 `result.kind` 区分「胜局 / 和棋 / 判负 / 已取消」并用中性或警告色，离线回放仍沿用「`winner` 是数字即胜局、没有 `winner` 即和棋」的旧口径，于是判负会显示成「胜局」、取消会显示成「和棋」。要两边都对齐，需同时改 `replay/markup.mjs` 的 `pillHtml` / `isDraw` 与终局卡的 `data-kind`——那会改动导出产物与视频画面，留待单独决定。
- 观战侧的终局强调只做终局：将军压暗与红环脉冲、吃子碎裂、关键手进度刻度仍只在离线回放与视频里出现。象棋 `match.state.moves[i]` 已带 `check` / `captured`，观战要补这些不需要重放规则，属于下一轮的事。（狼人杀席位舞台的逐手重画不在此列：存活、天数与阶段不重放规则就画不出来，已由 `werewolf-projection.mjs` 补上。）
- **判负的解释只做在观战页。** 判负裁决的是协议遵守度、不是棋力，只留一句「连续违规，判负」会被读成系统故障或棋力失败：结果行下面因此补一块判罚明细——「第几手、连续几次、每次为什么、盘面停在哪」，逐次原因与原始回复折进可展开的 `details`；负方席位挂「负」徽标（`finaleInfo.loser`），回合记录里补一条「未落子」条目，让记录不再从最后一手直接跳到判负。明细由 `presentation.forfeitDetail` 从 `events.invalid` 的 `error` / `raw` 派生，手数用同一回合的 `request` 事件补（每次重试都换新 `turnId`，不能按 `turnId` 分组），不动 `match.json` 与 RPC，历史对局自动生效；违规那一手的 `speech` 从未生效，因此不进回合记录的正常发言流。离线回放、视频与 Markdown 战报仍只印一句结果（回放还把判负显示成「胜局」，见上一条），这是与上一条同源的措辞差异，本轮刻意只做观战页。
- `boardSvg` 自身排版：左侧行号中心在 x=18、第一列棋子左缘也在 x=18，两者重叠，满幅放大后比原先更明显。观战、离线回放、视频三处共用同一份棋盘绘制，是否调整需单独决定。
- 象棋不裁决正式中国象棋的长将、长捉责任归属，也不做长将判负。1.1.0 的选择是：既然不裁决责任，就不再用次数把棋局判死——重复只作提示，停滞交给无进展规则收口。这带来两个后果：劣势方无法靠重复立刻求和（对局变长），优势方打摆子也不会被判负（只是浪费手数）。若要按正式规则裁决长将/长捉，需要扩展「每手是否将军、被威胁子是谁」的记录协议，并重新引入带责任归属的重复裁决。
- 取消重复判和后，停滞棋局要走满 120 半回合才结束，长局的模型调用成本随之上升。真实长局的上界约一万手，只由无进展规则与不可逆事件数量决定。
- 狼人杀只有 6 / 8 / 9 三个档位，且仍是简化局：没有警长、自爆、遗言、守卫，也不判平局；猎人开枪在画面上不区分死因，只靠白天/夜景区分。8 / 9 人的牌型只做过屠城判据下的配比推算，尚未经过真实模型的平衡验收。
- 主持人是确定性播报，不是 AI 即兴解说：台词由规则事件拼装，不解释局势、不点评选手。1.0.0 的历史局面没有 `narration`，直播侧停在最新一手时退回公开记录的最后一条（第三人称口径）；往回拖或离线回放由新规则重放后会补上主持人台词，因此同一场旧对局在「最新一手」与「拖回任意一手」之间会有一次口径切换。人数档位化把规则版本升到 1.1.0，回放门禁因此从「版本相等」放宽为「档位可重放」，否则旧对局会退化成「只播发言、不画身份」。
- 主持人配音有三条边界：终局卡只在狼人杀最后一条结算播报有配音时拉长，其余保持 4 秒，胜负由终局卡文字宣布；一手内主持人先说、选手后说，但画面上的「本手发言」字幕从这一手开头就显示，主持人播报期间字幕会先于声音出现；主持人台词按「换句」合成，因此同一句白天引导在整局里只合成一次、在它生效的那一手播放。
- 夜间结算的画面与台词差一拍：狼刀与毒药的出局（红叉、灰化、「出局」标记）画在「女巫用药」那一帧，主持人的「天亮了，昨夜 X 号出局」则在下一帧（天亮后的第一位发言者）说出来。这是「主持人先说、选手后说」的必然结果——结算播报属于下一步的开场，画面上的出局标记仍是规则推进的真实反映。
