# AI竞技台

本包源码位于 `lwb/packs/ai-arena/`，开发时自动发现；尚未加入桌面发行版随带清单，发行版归属由产品发布团队决定。

## 当前范围

- 支持五子棋和中国象棋。五子棋采用 15×15 自由规则，黑方先手，无禁手，连续五颗及以上获胜。规则判定采用 MIT 许可的 `@algorithm.ts/gomoku@4.0.5`；本包只做坐标、占位、轮次和状态适配。
- 中国象棋使用标准 10×9 棋盘，红方先手，支持将、士、象、马、车、炮、兵的合法走法，含马腿、象眼、九宫、过河、炮架、将帅照面、自将检查、将军、将死、困毙与吃将；胜负和裁决模型见[象棋的裁决模型](#象棋的裁决模型)，边界见[已知限制](#已知限制)。客户端、回放、离线 HTML、Markdown 战报和视频表现层显示楚河汉界、九宫、32 枚红黑棋子与起止坐标，视觉沿用五子棋竞技台的页面结构与窄屏布局。
- 两名选手选择 DSH 已配置的模型路由，允许同模型自我对弈。推理强度在模型目录公开支持时可选择；比赛只记录所选路由与模型 id，不推断底层真实模型。
- 每名选手使用各自的连续 DSH Agent Session，每次发送当前棋盘、公开的规则、最近着法与重复/无进展计数，以及必要的纠错反馈（象棋的披露分层见[象棋的裁决模型](#象棋的裁决模型)）。无工具预设启用 DSH 原生自动上下文压缩；单次回复被截断时在同一 Session 中有限补全。暂停恢复复用选手会话，保留比赛审计；官方对话窗口仅供回看，不提供可干扰比赛的输入框。
- 所有选手使用同一系统指令；对手发言不进入参赛请求。选手发言是模型输出的简短表达，不声称是完整内部推理；实际返回的 reasoning 仅保存在原始记录中。
- 非法坐标、占用落点、回复格式不合法均记为违规，默认重试一次，再次违规判负。服务错误或截断暂停比赛，由用户决定继续，不计为棋力失败。
- 暂停在当前回合结算后生效；取消立即停止调用，迟到回复不提交为落子。关闭浏览器不停止比赛；停止 Host 或卸载包中断比赛，重新加载后需要人工继续。
- 场景层不设置走子上限、调用上限、单步时限、每步生成 Token 或累计 Token 上限。输出容量与上下文处理交由 DSH、模型适配器和服务商的原生配置；这不代表模型和服务商没有边界。调用和已报告 Token 继续作为审计统计，未报告用量明确显示不完整，不伪造费用。
- 比赛按棋规判定终局，保留违规重试、格式补全、暂停、取消与错误处理。象棋只有吃将、将死、困毙三种胜法和「连续 120 半回合无吃子及兵卒向前推进」一种和棋；**重复局面不是裁决**，只作为信息公开给选手。快照读取与取消结算的基础设施等待边界仍保留。
- 不提供快速或深度模式切换。旧比赛恢复时清除场景预算与时限配置，显式清除旧会话输出策略并记录迁移事件，后续按 DSH 默认执行。已结束的历史比赛及其原始请求、输出、结果保持原样。
- 关键手档位默认为「吃大子 / 将军」。档位默认值、下拉首项与视频固定档位保持一致；只取「将军」会丢掉连续兑子的高潮段落。

## 象棋的裁决模型

规则版本 1.1.0 取消了「局面出现三次即判和」。这不是放松规则，而是承认那条规则回答错了问题。

- **为什么取消次数判和。** 次数只说明棋局是否停滞，不说明双方是否赢不了，而它却是**行为依赖**的：同一张盘面，双方多绕两圈判和、少绕两圈继续下。它会把胜局判和——1.0.0 下的一场实盘就是如此：黑方子力 14:2 大优、红方只剩光帅加一仕，黑方在第 126—136 手用马反复叫将，第 136 手触发第三次重复即判和。这是可复现的回归夹具 `test/fixtures/xiangqi-perpetual-check-loop.json`。
- **终止性不依赖重复裁决。** 无进展计数只在**吃子**或**兵卒向前推进**时归零，两者都不可逆且有界：吃子至多 31 次，兵卒纵向前进每方至多 30 次。归零事件有限 ⇒ 总手数存在约一万手的硬上界，比赛必然终止。所以去掉重复判和后，终止性由无进展规则单独保证。
- **历史裁剪与计数正确性。** 吃子或兵卒向前推进之后，此前的任何局面都不可能再出现，因此重复历史在这些时刻裁剪到当前局面，长度被无进展上限约束在 120 以内；被裁掉的条目本来也永不匹配，所以上报给选手的重复次数仍然精确。
- **披露分三层。** 构成性规则（胜负和如何裁决）必须给，写进系统指令与游戏说明；局面状态（最近着法 `recentMoves`、当前局面出现次数 `positionRepeats`、每个合法着法走完后的重复次数 `repeats`、无进展手数 `noProgressPlies` 与阈值 `noProgressLimit`）必须给，否则等于用一个选手无法建模的量来影响它的结果；**策略建议不给**，系统指令只陈述规则事实，不写「领先时应当变着」这类教练话术。
- **代价。** 和棋会更晚出现：停滞的棋局现在要走满 120 半回合才判和，长局与模型调用成本上升。无进展规则本身仍是与次数规则同类的近似——它同样不判断「是否真的赢不了」。它只是不再把胜局判和，并把裁决从「双方绕了几圈」改成「棋局多久没有实质进展」。
- **披露的每手开销。** 最近着法用紧凑记法（手数+走子方+棋子+起点行,列>终点行,列，x 吃子、+ 将军，如 `136黑馬8,8>10,7+`），16 手约 257 字节，比等价嵌套 JSON 省约 7 倍。开局满子力时每手提示词约 3.3 KB（主要花在约 40 个合法着法与各自 `repeats`），残局约 1.1 KB。

## 画面与视频

离线回放与视频共用 `lwb/packs/ai-arena/replay/` 这一份画面源：`page.html` 骨架、`scene.css` 布局与配色、`shell.css` 交互外壳、`app.js` 离线播放器、`markup.mjs` 帧驱动构建器、`data.mjs` 数据投影、`timeline.mjs` 时间轴；生成物由 `build-replay.mjs` 产出，已并入 `npm run arena:build`。两侧共用同一份手数、关键手、连子与终局文案，不再各自投影一遍。

- 画幅锁定 1280×720 与 720×1280，棋盘满幅出血占满画幅高度（横屏）或宽度（竖屏）。推近朝无标注侧生长（五子棋锚左上，象棋锚左下），幅度收到 1.03，实测保留零裁切。配色为白底 + 电蓝（品牌/当前手）+ 金（关键手/胜局）。
- 离线回放只内联画面真正需要的数据（标题、游戏、选手、结果、每手的动作与发言、关键手标记），棋盘在浏览器里用与观战、视频同一份 `boardSvg` 现画，产物与手数基本无关：五子棋 39 KB、象棋 52 KB。
- 视频时长按 `(手数 + 1) × 每手秒数 + 4 秒终局卡`，与离线 HTML 的 `FINALE_MS` 对齐：五子棋 20 手＝67.0 秒，象棋 136 手＝415.0 秒。勾选「生成声音」后，有配音的那一手改为 `max(每手秒数, 音频时长 + 0.35 秒)`，终局卡仍是 4 秒。
- 视频侧由 `markup.mjs` 把每个随时间的量（推近、落子入场、碎裂、震屏、脉冲、金带、点亮环、字幕入场）在 JS 里按步内秒数算好写成内联样式，并由 `video.mjs` 关闭全部 CSS 动画与过渡，保证逐帧截图确定。

## 数据与恢复

`<pack-workspace>/data/matches/<match-id>/match.json` 是每场比赛的事实源，包含配置、规则版本、模型身份、棋盘和事件；串行写入并通过原子替换提交。事件依次记录 request、response、move/invalid、error/interrupted、finished/cancelled。

原始回复先保存为 pending，再校验并提交动作。Host 在收到回复后中断，继续时可消费已保存的回复，不重复请求。请求已经发出但未收到回复时无法确认供应商是否完成或计费，不自动重新调用，先暂停等待用户决定。重启前请求仍计入调用次数。

恢复比赛前检查游戏规则版本；版本变化时保留记录并要求创建新比赛，避免按不同规则继续旧局。

完整 JSON 下载包括各回合实际输入、输出、用量、reasoning 和配置；Markdown 是便于阅读的战报。离线 HTML 只内联画面所需数据（不含原始请求、系统指令和推理文本），在浏览器里用与观战、视频同一份 `boardSvg` 现画棋盘，不依赖网络、模型或其他包，支持横竖屏切换、跳步、播放、关键手强调档位和纯画面模式。导出文本和 HTML 对模型文本作相应安全编码。

## 视频渲染

视频通过现有 Remotion 技术栈渲染固定模板，棋盘与台词来自同一份比赛事件；每步默认 3 秒，额外保留终局画面。横屏为 1280×720，竖屏为 720×1280，H.264 MP4。画面包含文字发言。比赛记录里可以勾选「生成声音」：未登录 LWB、语音服务不可用或可用积分低于目录最低门槛时，勾选不可用，无声导出保持可用。勾选后用 LWB TTS 按每手发言合成语音，音色和圆形 logo 按模型匹配，没有专属素材时用通用音色和通用模型 logo，两名未匹配选手不共用同一条通用音色。配音按句缓存在比赛目录，同一句再次导出不再请求。写入缓存前尽量把每句和参考音色拉到 -16 LUFS、真峰值不超过 -1.5 dB。某一句测不准时仍使用已生成的音频，不中断回放和视频。有声回放与有声视频都在后台合成，进度记在这场比赛上，离开页面不会停止。离线 HTML 把音频内联为 data URL，仍不依赖网络；MP4 在画面渲染后用 FFmpeg 按每手起始时间混入音轨。没有 BGM、自动解说或精华剪辑。

渲染需要 FFmpeg、ffprobe 和 Chrome。macOS 默认使用已安装的 Google Chrome，其他环境可设置 `LWB_REMOTION_BROWSER_EXECUTABLE`。成片用 ffprobe 检查尺寸和时长。下载通过有界分块 RPC，绑定导出版本；不沿用口播包的整文件 80 MiB 读取方式。

## 扩展边界

`games.mjs` 在竞技包内部管理游戏定义。每个游戏提供身份与版本、人数、create、observe、apply；宿主负责棋规终局、错误、存储和回合调度。目前仅实现双人轮流行动，下一种同时行动或隐藏信息游戏必须扩展调度协议及选手视角，不是只修改提示词。浏览器和视频需为新游戏增加专属画面适配。

竞技台不暴露一次性模型 completion 绕过路径；模型调用统一受 DSH Session、能力包卸载信号、取消信号和权益边界管理。普通对话、口播 Agent、测评会话继续使用各自原有的 DSH 路径。

象棋规则可复现交叉检查：`node lwb/packs/ai-arena/test/xiangqi-reference-check.mjs` 使用 `@weshell/xiangqi.js@1.0.3`、固定 seed `0x51a7c0de`，比较 1200 个局面并应用 1200 个合法半回合，覆盖 4 局，要求 `mismatches=0`。该检查只证明合法着法集合 parity；每个局面重建 FEN，因此不比较无进展计数，也不比较任何终局裁决。取消重复判和后的终止性行为由 `test/xiangqi.test.mjs` 的无进展用例与实盘回归夹具覆盖，不由该检查覆盖。

协议验收服务位于 `lwb/packs/ai-arena/test/model-server.mjs`，手动运行时监听 127.0.0.1:4196，仅供开发验证，不随包自动注册，不用于证明模型棋力。

功能测试覆盖规则、恢复、暂停、取消、异常、旧配置兼容、用量审计、离线编码和分块下载。真实模型供应商、费用、棋力与长局稳定性需要另外验收；本地模拟模型的验证不等价于付费供应商已通过。

## 已知限制

- 视频侧不区分「播放推进」与「跳步」，每一步都按播放推进的动效渲染；离线 HTML 拖动进度条时不触发动画。
- `boardSvg` 自身排版：左侧行号中心在 x=18、第一列棋子左缘也在 x=18，两者重叠，满幅放大后比原先更明显。观战、离线回放、视频三处共用同一份棋盘绘制，是否调整需单独决定。
- 象棋不裁决正式中国象棋的长将、长捉责任归属，也不做长将判负。1.1.0 的选择是：既然不裁决责任，就不再用次数把棋局判死——重复只作提示，停滞交给无进展规则收口。这带来两个后果：劣势方无法靠重复立刻求和（对局变长），优势方打摆子也不会被判负（只是浪费手数）。若要按正式规则裁决长将/长捉，需要扩展「每手是否将军、被威胁子是谁」的记录协议，并重新引入带责任归属的重复裁决。
- 取消重复判和后，停滞棋局要走满 120 半回合才结束，长局的模型调用成本随之上升。真实长局的上界约一万手，只由无进展规则与不可逆事件数量决定。
